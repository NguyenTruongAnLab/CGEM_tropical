# C-GEM Tropical — 1-D Reactive-Transport Model for Tidal Estuaries

C-GEM is a one-dimensional, **tidally-resolved** reactive-transport model that
couples hydrodynamics (Saint-Venant equations with configurable `DELTI`),
sediment dynamics, eutrophication (NPZD), and carbonate chemistry in a single
framework. The bundled tropical-estuary example currently uses `DELTI = 360 s`.
It is designed for research on tropical and subtropical tidal estuaries.

---

## Quick Start

```bash
# 1. Clone
git clone https://github.com/NguyenTruongAnLab/CGEM_tropical.git
cd CGEM_tropical

# 2. Build (requires CMake ≥ 3.15 and a C99 compiler)
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release

# 3. Run the bundled example configuration
./bin/Release/C_GEM_Daily          # Linux / macOS
bin\Release\C_GEM_Daily.exe        # Windows
```

Per-variable outputs are written to `OUT/` as CSV by default. Set
`output_storage_format = BINARY` in `INPUT/params.txt` to write faster `.bin`
files instead; the public Python tools read both formats.

> **Tip:** Set `CGEM_PARAMS_PATH` to point to an alternate parameter file
> without editing the default `INPUT/params.txt`.

## Typical user workflow

Most users will follow this sequence:

1. **Download or clone the repository**.
2. **Build the executable** (or use a portable release archive).
3. **Review and edit the `INPUT/` directory** for your estuary. The main
   configuration surface is:
	- `params.txt`
	- `config_input.txt`
	- boundary and tributary forcing files
	- geometry and validation data
4. **Run the model** to generate outputs in `OUT/`.
5. **Make figures and validation plots** with the Python tools in `tools/`.

## What to prepare in `INPUT/`

The source code is generic; the estuary-specific setup lives in `INPUT/`.

- `INPUT/params.txt` — model parameters and runtime configuration
- `INPUT/config_input.txt` — where each boundary/tributary file is read from
- `INPUT/Boundary/` — upstream/downstream and meteorological forcing
- `INPUT/Tributaries/` — lateral inflow discharge and chemistry
- `INPUT/Geometry/river_bed_profile.txt` — longitudinal bed profile
- `INPUT/Validation/` — optional observation tables used by the plotting tools

The bundled forcing files are numeric two-column time series. See
`INPUT/README.md` and `Documentation/Getting-Started.md` before replacing them.

## What you get in `OUT/`

After a successful run, `OUT/` contains:

- one file per simulated state variable or diagnostic
	(for example `Sal.csv`, `O2.csv`, `velocity.csv`, or `.bin` equivalents in
	binary mode)
- optional flux and reaction diagnostics when enabled in `INPUT/params.txt`
- geometry output for plotting (`geometry.csv`, always written as CSV)
- figure and table products generated by the analysis scripts

Common follow-up commands are:

```bash
python tools/check_inputs.py
python tools/plot_profiles.py --output-dir OUT --with-obs
python tools/plot_hydrodynamics.py --output-dir OUT --with-obs
python tools/plot_seasonal.py --output-dir OUT --with-obs
```

## How to Adapt C-GEM to Your Estuary

1. **Prepare geometry** — bed profile, estuary length, tidal amplitude
2. **Prepare forcing data** — upstream discharge, downstream tide, meteorology
3. **Configure tributaries** — add/remove entries in `config_input.txt`
4. **Calibrate** — use the four-stage approach (hydro → sediment → biogeochem → carbonate)
5. **Validate** — compare model output against independent observations

See the [Getting Started](Documentation/Getting-Started.md) guide for details.
